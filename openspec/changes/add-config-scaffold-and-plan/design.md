# Design: config scaffold (`init`) and source-only plan

## Problem

```text
Today                          After this change
─────                          ─────────────────
Copy example YAML              privaci init --source … --output mask-rules.yaml
Hand-write every column        Review/edit generated file
Need target for dry-run        privaci plan --config … (source only)
Run                           privaci dry-run (when target exists) → privaci run
```

## Locked decisions

| Decision | Choice |
| --- | --- |
| `init` scope | Source **read-only** introspect + autodetect → write YAML |
| `init` output | Valid `mask-rules.yaml` v1.0; `auto_detect: true`, `strict_autodetect: false` |
| Uncertain columns | Included in YAML as comments **or** omitted with plan warnings — prefer comments + `review:` lines in plan |
| `plan` vs `dry-run` | **`plan`** = source only; **`dry-run`** = source + target preflight (unchanged) |
| `plan` output | Default human table/column summary; `--format json` for CI |
| Target for `init` | **Not required** |
| Target for `plan` | **Not required** |
| Overwrite | `init` refuses existing output unless `--force` |
| Salt in generated YAML | `global_salt: "${ANONYMIZATION_SALT}"` (env ref, never inline secret) |

## `privaci init` flow

```text
SOURCE_DB_URL / --source
        │
        ▼
  introspect_catalog (read-only)
        │
        ▼
  scan_catalog (autodetect) — same rules as run pipeline
        │
        ▼
  build Config skeleton:
    • one tables[] entry per source table (public schema default; --schema repeatable)
    • strategy: transform | exclude (exclude tables with no PK and no config need)
    • columns: action from autodetect findings (high confidence only in YAML)
        │
        ▼
  write mask-rules.yaml (+ stdout summary of uncertain columns)
```

### CLI sketch

```bash
privaci init \
  --source "$SOURCE_DB_URL" \
  --output mask-rules.yaml \
  [--schema public] \
  [--force]
```

Exit codes: **0** success, **2** config/connection error, **3** strict issues if
`--strict-output` added later (v1: warn only).

## `privaci plan` flow

```text
config + SOURCE_DB_URL
        │
        ▼
  load_config → introspect source → build_detection (merge config + autodetect)
        │
        ▼
  emit plan (no target connection, no writes)
```

### CLI sketch

```bash
privaci plan --config mask-rules.yaml [--source …] [--format text|json]
```

JSON schema (sketch):

```json
{
  "tables": [
    {
      "table": "public.users",
      "strategy": "transform",
      "estimated_rows": 50000,
      "columns": [
        {"name": "email", "action": "fake", "provider": "email", "source": "autodetect"},
        {"name": "notes", "action": null, "confidence": "medium", "source": "autodetect"}
      ]
    }
  ],
  "summary": {"mask": 12, "review": 3, "copy": 5}
}
```

Human text output reuses/enhances `_render_dry_run_summary` column lines without target checks.

## Relationship to existing commands

| Command | Source | Target | Writes target |
| --- | --- | --- | --- |
| `catalog inspect` | Yes | No | No |
| `init` | Yes | No | No (writes YAML file only) |
| `plan` | Yes | No | No |
| `dry-run` | Yes | Yes | No |
| `run` | Yes | Yes | Yes |

## Security

- **Read-only** source queries only for `init` and `plan`.
- Generated YAML must not embed DSN passwords — use env refs in docs/comments only.
- Log/echo must not print PII sample values from source rows.
- Header comment in generated file: `# Generated by privaci init — review before production run.`

## Onboarding path

Typical operator flow after deploy:

```text
Deploy engine → privaci init → privaci plan → edit YAML → dry-run → run
```
